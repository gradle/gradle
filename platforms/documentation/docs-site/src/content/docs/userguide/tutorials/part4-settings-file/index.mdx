## Step 1. Gradle scripts

Build scripts and setting files are code.
They are written in Kotlin or Groovy.

You use the [Kotlin DSL](https://docs.gradle.org/current/kotlin-dsl/), [Groovy DSL](https://docs.gradle.org/current/dsl/) and [Gradle APIs](https://docs.gradle.org/current/javadoc/) to write the scripts.

The methods that can be used within a Gradle script primarily include:

- Gradle APIs - such as `getRootProject()` from the <JavaDocLink class="org.gradle.api.initialization.Settings">Settings API</JavaDocLink>
- Blocks defined in the DSL - such as the `plugins{}` block from <KotlinDocLink class="org.gradle.kotlin.dsl.KotlinSettingsScript" />
- Extensions defined by Plugins - such as `implementation()` and `api()` provided by the `java` plugin when applied

## Step 2. The `Settings` object

The settings file is the entry point of every Gradle build.

During the initialization phase, Gradle finds the settings file in your project root directory.

When the settings file, `settings.gradle(.kts)`, is found, Gradle instantiates a <GroovyDocLink class="org.gradle.api.initialization.Settings" /> object.

One of the purposes of the <GroovyDocLink class="org.gradle.api.initialization.Settings" /> object is to allow you to declare all the projects to be included in the build.

You can use any of the methods and properties on the <GroovyDocLink class="org.gradle.api.initialization.Settings" /> interface directly in your settings file.

For example:

<Tabs syncKey="script-language">
<TabItem label="Kotlin">

```kotlin
includeBuild("some-build")                         // Delegates to Settings.includeBuild()
reportsDir = findProject("/myInternalProject")     // Delegates to Settings.findProject()
```

</TabItem>
<TabItem label="Groovy">

```groovy
includeBuild('some-build')                         // Delegates to Settings.includeBuild()
reportsDir = findProject('/myInternalProject')     // Delegates to Settings.findProject()
```

</TabItem>
</Tabs>
