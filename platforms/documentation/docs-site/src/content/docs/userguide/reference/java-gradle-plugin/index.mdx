The Java Gradle Plugin development plugin can be used to assist in the development of Gradle plugins.
It automatically applies the <Xref page="java-library-plugin" section="The Java Library Plugin">Java Library (`java-library`)</Xref> plugin, adds the `gradleApi()` dependency to the `compileOnlyApi` configuration and performs validation of plugin metadata during `jar` task execution.

The plugin also integrates with <Xref page="test-kit" section="Testing Build Logic with TestKit">TestKit</Xref>, a library that aids in writing and executing functional tests for plugin code.
It automatically adds the `gradleTestKit()` dependency to the `testImplementation` configuration and generates a plugin classpath manifest file consumed by a `GradleRunner` instance if found.
Please refer to <Xref page="test-kit" section="Automatic injection with the Java Gradle Plugin Development plugin">Automatic classpath injection with the Plugin Development Plugin</Xref> for more on its usage, configuration options and samples.

## Usage

To use the Java Gradle Plugin Development plugin, include the following in your build script:

<SampleScripts sample_name="java-gradle-plugin" basename="build" tag="use-java-gradle-plugin-plugin" source_dir="snippets/reference/core-plugins/javaGradlePlugin" />

Applying the plugin automatically applies the <Xref page="java-library-plugin" section="The Java Library Plugin">Java Library(`java-library`)</Xref> plugin and adds the `gradleApi()` dependency to the `api` configuration.
It also adds some validations to the build.

The following validations are performed:

- There is a plugin descriptor defined for the plugin.
- The plugin descriptor contains an `implementation-class` property.
- The `implementation-class` property references a valid class file in the jar.
- Each property getter or the corresponding field must be annotated with a property annotation like `@InputFile` and `@OutputDirectory`.
Properties that don’t participate in up-to-date checks should be annotated with `@Internal`.

Any failed validations will result in a warning message.

For each plugin you are developing, register it into the `gradlePlugin {}` script block:

<SampleScripts sample_name="java-gradle-plugin" basename="build" tag="gradle-plugin-block" source_dir="snippets/reference/core-plugins/javaGradlePlugin" />

The `gradlePlugin {}` block defines the plugins being built by the project.
The plugin `id` is set from the registration name, here `org.gradle.sample.simple-plugin`.
Then, you define the `implementationClass` of the plugin, here `org.gradle.sample.SimplePlugin`.

You can override the plugin `id` by explicitly setting the `id` property such as `id = "convention-plugin"`.

From this data about the plugins being developed, Gradle can automatically:

- Generate the plugin descriptor in the `jar` file’s `META-INF` directory.
- Configure the <Xref page="plugins-intermediate" section="Plugin Marker Artifacts">Plugin Marker Artifact</Xref> publications (Maven or Ivy) for each plugin.
- Publish each plugin to the Gradle Plugin Portal (see <Xref page="publishing-gradle-plugins" section="Publishing Plugins to the Gradle Plugin Portal">Publishing Plugins to Gradle Plugin Portal</Xref> for details), but only if the [Plugin Publishing Plugin](https://plugins.gradle.org/docs/publish-plugin) has also been applied.

## Interactions

Some of the plugin’s behaviour depends on other, related plugins also being applied in your build, namely the <Xref page="publishing-maven" section="The Maven Publish Plugin">Maven Publish (`maven-publish`)</Xref> and <Xref page="publishing-ivy" section="The Ivy Publish Plugin">Ivy Publish (`ivy-publish`)</Xref> plugins.

Other plugins auto apply the Java Gradle Plugin, like the [Plugin Publishing Plugin](https://plugins.gradle.org/plugin/com.gradle.plugin-publish).

### Maven Publish Plugin

When the Java Gradle Plugin (`java-gradle-plugin`) detects that the Maven Publish Plugin (`maven-publish`) is also applied by the build, it will automatically configure the following <GroovyDocLink class="org.gradle.api.publish.maven.MavenPublication">MavenPublications</GroovyDocLink>:

- a single "main" publication, named `pluginMaven`, based on the <Xref page="java-plugin" section="Publishing">main Java component</Xref>
- multiple <Xref page="plugins-intermediate" section="Plugin Marker Artifacts">"marker" publications</Xref> (one for each plugin defined in the `gradlePlugin {}` block), named `<pluginName>PluginMarkerMaven` (for example in the above example it would be `simplePluginPluginMarkerMaven`)

This automatic configuration happens in a <GroovyDocLink class="org.gradle.api.Project" method="afterEvaluate(org.gradle.api.Action)">Project.afterEvaluate()</GroovyDocLink> block (so at the end of the <Xref page="build-lifecycle" section="Build Phases">build configuration phase</Xref>), and only if these publications haven’t already been defined, so it’s possible to create and customise them during the earlier stages of build configuration.

### Ivy Publish Plugin

When the Java Gradle Plugin(`java-gradle-plugin`) detects that the Ivy Publish Plugin (`ivy-publish`) is also applied by the build, it will automatically configure the following <GroovyDocLink class="org.gradle.api.publish.ivy.IvyPublication">IvyPublications</GroovyDocLink>:

- a single "main" publication, named `pluginIvy`, based on the <Xref page="java-plugin" section="Publishing">main Java component</Xref>
- multiple <Xref page="plugins-intermediate" section="Plugin Marker Artifacts">"marker" publications</Xref> (one for each plugin defined in the `gradlePlugin {}` block), named `<pluginName>PluginMarkerIvy` (for example in the above example it would be `simplePluginPluginMarkerIvy`)

This automatic configuration happens in a <GroovyDocLink class="org.gradle.api.Project" method="afterEvaluate(org.gradle.api.Action)">Project.afterEvaluate()</GroovyDocLink> block (so at the end of the <Xref page="build-lifecycle" section="Build Phases">build configuration phase</Xref>), and only if these publications haven’t already been defined, so it’s possible to create and customise them during the earlier stages of build configuration.

### Plugin Publish Plugin

Starting from [version 1.0.0, the Plugin Publish Plugin](https://plugins.gradle.org/plugin/com.gradle.plugin-publish/1.0.0) always auto-applies the Java Gradle Plugin (`java-gradle-plugin`) and the Maven Publish Plugin (`maven-publish`).
